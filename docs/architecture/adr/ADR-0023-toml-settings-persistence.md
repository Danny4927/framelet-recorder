# ADR-0023: Persist recording settings as a TOML file in a dedicated settings adapter

- **Date:** 28 November 2026
- **Status:** Proposed — implements the maintainer decision of 28 November 2026 (crate, format, location, atomic write, fallback); the schema, defaults, value ranges, port change, and dependency review below await maintainer acceptance
- **Amends (on acceptance):** ADR-0012 decision 7 — the settings port keeps "serialization and platform-specific locations in the adapter" but its signature changes (decision 2). The accepted text of ADR-0012 is not edited.
- **Related:** ADR-0010, ADR-0011, ADR-0012, ADR-0014, ADR-0021, ADR-0022; roadmap C2 and criterion C-7; SPECIFICATION.md §7.1 (REQ-CFG-01 … REQ-CFG-05)

## Context

Roadmap deliverable C2 needs a TOML settings adapter behind `RecordingSettingsPort`, and criterion C-7 needs tests for missing, malformed, out-of-range, and unwritable settings files. Until now the crate, the serialization dependency, the on-disk schema, and the default/out-of-range policy were undecided (roadmap note on C-7).

The maintainer decided on 28 November 2026: a new crate `crates/settings`; `toml` + `serde` (derive); location Linux `$XDG_CONFIG_HOME/framelet/settings.toml` (fallback `$HOME/.config/framelet/settings.toml`) and Windows `%APPDATA%\Framelet\settings.toml`, resolved from standard environment variables without a `dirs`/`directories` crate; atomic write (temporary file in the same directory, then rename); fallback to safe defaults with a typed, user-visible error; never panic, never partially overwrite.

The existing port (ADR-0012) could not express that decision:

- `load(&self) -> Result<RecordingSettings, PortError>` cannot return "defaults *and* an error the user must see", and cannot distinguish "nothing stored yet" (not a failure) from "stored settings rejected".
- `PortError` carries free-form strings; the reason (malformed, unknown version, invalid value, unwritable) would be stringly typed.
- `RecordingSettings::output_directory` was an unvalidated `String` with no way to say "use the platform default directory".

The port had no consumer (roadmap A6), so changing it now costs nothing outside the core.

## Decision

### Core: settings value objects and port (`framelet_core::settings`, `framelet_core::ports`)

1. **Value objects, no serde.** `RecordingSettings { output_directory: Option<OutputDirectory>, microphone_enabled_by_default: bool }` lives in the new core module `settings` (re-exported from `ports`). `OutputDirectory` is a validated value object (invariants in decision 10). `RecordingSettings::default()` is the safe default. Core types do not derive or name serde; `scripts/check-architecture.py` forbids serde/toml in every first-party manifest except `crates/settings/Cargo.toml` and forbids `serde`/`toml::` references in core sources.
2. **Port.** `RecordingSettingsPort::load(&self) -> LoadedSettings` (infallible) and `save(&self, &RecordingSettings) -> Result<(), SettingsError>`. `LoadedSettings { settings, origin }` with `SettingsOrigin::{Stored, DefaultsNotStored, DefaultsAfterError(SettingsError)}`; `LoadedSettings::error()` returns the error to show, which is `None` for `Stored` and for `DefaultsNotStored`.
3. **Typed errors.** `SettingsError::{LocationUnavailable, TooLarge { limit_bytes }, Malformed { line }, MissingSchemaVersion, UnsupportedSchemaVersion { found, supported }, SchemaMismatch { line }, InvalidOutputDirectory(OutputDirectoryViolation), ReadFailed(SettingsIoFailure), WriteFailed(SettingsIoFailure)}`, with `SettingsIoFailure::{PermissionDenied, ReadOnly, StorageFull, NotAFile, Other}`. No native error type and no file content crosses the port; line numbers are the only location information. `Display` gives an actionable English message; translation belongs to the UI.
4. **Contract** (documented on the port, suite `framelet_core::contract::settings`): `load` never fails and never modifies or deletes stored settings; missing → defaults as `DefaultsNotStored`; unusable → defaults with `DefaultsAfterError`; `save` is all-or-nothing, a failed save returns `WriteFailed` and leaves the previous settings loadable; methods run on a worker, never on the UI thread. The core fake `FakeSettings` and the TOML adapter both pass the suite.

### Adapter: `crates/settings` (`framelet-settings`, `TomlSettingsFile`)

5. **Crate.** `#![forbid(unsafe_code)]`; depends on `framelet-core`, `serde =1.0.229` (feature `derive`), and `toml =1.2.3` (`default-features = false`, features `std`, `serde`, `parse`, `display` — the upstream defaults made explicit). The serde DTO `SettingsFileV1` is private to `src/schema.rs`.
6. **Location** (`TomlSettingsFile::from_environment`): Linux — `$XDG_CONFIG_HOME/framelet/settings.toml` if `XDG_CONFIG_HOME` is set, non-empty, and absolute (XDG Base Directory specification: a relative value is ignored), else `$HOME/.config/framelet/settings.toml` if `HOME` is non-empty and absolute; Windows — `%APPDATA%\Framelet\settings.toml` if `APPDATA` is non-empty and absolute. Otherwise `SettingsError::LocationUnavailable`; the caller uses defaults and shows it. Only `std::env::var_os` is used.
7. **Schema version 1** (written with a comment header):

   | Key | Type | Required | Absent means | Valid values |
   |---|---|---|---|---|
   | `schema_version` | integer | yes | `MissingSchemaVersion` | exactly `1`; any other integer → `UnsupportedSchemaVersion` |
   | `microphone_enabled_by_default` | boolean | no | `false` | `true`, `false` |
   | `output_directory` | string | no | platform default directory (REQ-STOR-06) | see decision 10 |

   Any other key, or a value of the wrong type, is `SchemaMismatch` (`deny_unknown_fields`). A later build that adds a key must bump `schema_version`, so an older build reports "newer schema" instead of "unknown key"; newer builds keep a reader for every older version they accept.
8. **Load** reads at most `MAX_SETTINGS_FILE_BYTES` = 64 KiB + 1 byte (larger → `TooLarge`, unparsed), rejects a non-regular file — directory, FIFO, socket, or device — from its metadata *before* opening it, so a FIFO cannot block the load (`ReadFailed(NotAFile)`; the opened handle is checked again), rejects non-UTF-8 (`Malformed` with the line), then checks in this order: TOML syntax (`Malformed`), `schema_version` (`MissingSchemaVersion`/`UnsupportedSchemaVersion`), schema shape (`SchemaMismatch`), core invariants (`InvalidOutputDirectory`). The first failure rejects the **whole file**: no field of a rejected file is applied. Load never writes, so a rejected file stays on disk for the user to fix. Residual race: if the path is replaced by a FIFO between the metadata check and the open, the open can still block; closing that window needs a non-blocking open flag, which std exposes only through platform constants (a `libc` dependency or a hard-coded flag), so it is accepted and documented rather than worked around.
9. **Save** encodes in memory, refuses a read-only `settings.toml` (`WriteFailed(ReadOnly)`, file untouched — also on Linux, where rename would otherwise replace it) and a directory at the settings path, creates the settings directory if needed (Unix mode `0700`), creates `.settings.toml.<pid>.<n>.tmp` exclusively in the same directory (Unix mode `0600`; up to 16 names are tried when stale temporary files exist), writes, `sync_all`s, closes, and renames it over `settings.toml`. A failure at any step returns `WriteFailed`, removes the temporary file, and leaves `settings.toml` byte-for-byte unchanged. "Intact" throughout this ADR means: `settings.toml` is always either the complete old file or the complete new file, never a partial one. Because the parent directory is not fsynced after the rename, a completed save can revert to the old file after a power loss or crash; it cannot become partial. If the removal itself fails, the temporary file stays under its `.tmp` name, which `load` never reads. All write calls go through a crate-private `FileOperations` seam for fault injection, like the storage adapter (ADR-0014).

### Defaults and ranges — decisions for the maintainer to confirm

The specification gives no settings schema. These values are this ADR's proposal and are listed so they can be confirmed or changed explicitly:

10. **`OutputDirectory` invariant** (core, lexical, platform-aware): not empty or whitespace-only; at most `MAX_OUTPUT_DIRECTORY_BYTES` = 4096 UTF-8 bytes (Linux `PATH_MAX`; inclusive); no control characters (NUL, line breaks, escape sequences); absolute on the running platform (`Path::is_absolute`: `/…` on Linux, `C:\…` or `\\server\share\…` on Windows); no `..` component. Existence and writability are checked by the storage adapter when the directory is used, not here.
11. **Out-of-range policy: reject, do not clamp.** An invalid value makes the file unusable → defaults + `InvalidOutputDirectory`/`UnsupportedSchemaVersion`; nothing is silently corrected, because a corrected value would be a setting the user did not choose and was not told about (Spec §1.3 #8, REQ-DEV-02 spirit). The rejected file is preserved.
12. **Default output directory: none stored** (`None` → the platform default Videos/Framelet directory chosen by the composition root/storage, REQ-STOR-06). The settings adapter does not compute it, so there is no adapter-to-adapter coupling.
13. **Default `microphone_enabled_by_default = false`** — privacy by default (Spec §1.3 #2). Microphone-only mode records the microphone regardless.
14. **Unknown keys are rejected**, absent optional keys take defaults; a typo therefore produces a visible error instead of a silently ignored setting.
15. **File size limit 64 KiB** — a valid v1 file stays under 9 KiB even with the longest directory (4096 bytes, at most doubled by escaping).
16. **Spec §4.5 defaults are not persisted in schema v1.** Resolution, frame rate, sample rate, container, and codecs are negotiated per device/backend (REQ-DEV-02) and are not user options in the primary view (REQ-UX-04). Countdown (REQ-UX-06) and webcam bubble size/corner (REQ-PIP-04/05) are user options but have no core domain type or consumer yet; they are added, with their ranges, by the slices that consume them (C1 UI, G), through a schema version bump. Adding them now would be placeholder code.
17. **Symlinks and check-then-act:** `load` follows a symlinked `settings.toml`; `save` replaces the link itself (and likewise a FIFO or socket at the path) with a regular file (rename semantics) and never writes through it, so a user who keeps `settings.toml` as a symlink into a dotfiles repository loses the link on the first save. The read-only and directory checks before a save are check-then-act: if another process changes the path between the check and the rename (for example makes the file read-only, or swaps in a symlink), the change is not detected and the rename replaces whatever is there with the complete new file. This is accepted because only processes of the same user can write the settings directory, and they can rewrite the file anyway. **Concurrency:** two processes saving concurrently each write a complete file; the last rename wins; there is no lock. **Durability:** the file is flushed before rename, the directory is not fsynced, so power-loss durability is not claimed (same as ADR-0014). **Comments:** a save rewrites the file and drops user comments.

### Dependency review (AGENTS.md dependency policy, Spec §3.1)

Reviewed 28 November 2026 against crates.io, upstream changelogs, `cargo audit`, `cargo deny`, `cargo vet`, and the crate sources in the local registry.

1. **Why needed.** SPECIFICATION.md §3 names "serde + TOML" for config; the maintainer selected `toml` + `serde` derive. A hand-written TOML subset parser would be first-party parsing code of the same size as the adapter with none of the upstream test suite (`toml-test`); serde derive avoids hand-written field mapping for writing.
2. **Maintenance and releases.**

   | `toml_parser` | 1.1.7+spec-1.1.0 | 2026-11-25 | 1.1.7 | toml-rs/toml |
   | `toml_writer` | 1.2.0+spec-1.1.0 | 2026-11-04 | 1.2.0 | toml-rs/toml |
   | `toml_datetime` | 1.1.3+spec-1.1.0 | 2026-11-06 | 1.1.3 | toml-rs/toml |
   | `serde_spanned` | 1.1.3 | 2026-11-06 | 1.1.3 | toml-rs/toml |
   | `winnow` | 1.0.5 | 2026-11-05 | 1.0.5 | winnow-rs/winnow |

   | `proc-macro2` / `quote` / `syn` / `unicode-ident` | 1.0.107 / 1.0.47 / 3.0.10 / 1.0.27 | 2026-07-19 / 2026-07-19 / 2026-11-09 / 2026-10-12 | same | dtolnay |

   All are actively released, among the most-downloaded crates on crates.io, and MSRV ≤ 1.85 (workspace MSRV 1.92). `toml` 1.2.3 is three days old; it is pinned anyway because 1.2.2/1.2.3 (with `toml_parser` 1.1.6/1.1.7) fix a stack overflow on invalid TOML and on many dotted keys — a process abort the adapter cannot catch, reachable from a hand-edited settings file. The 1.2.1 → 1.2.3 diff of `toml` leaves `src/` unchanged; its manifest bumps the version and raises the `toml_parser` requirement from 1.1.5 to 1.1.7 (the fixes live there), and the packaging metadata (`.cargo_vcs_info.json`, bundled `Cargo.lock`) differs; the `toml_parser` 1.1.5 → 1.1.7 diff adds recursion-depth accounting for dotted keys and fixes bracket matching after a rejected value, in safe code.
3. **Licence and redistribution.** `MIT OR Apache-2.0` for all crates except `winnow` (`MIT`) and `unicode-ident` (`(MIT OR Apache-2.0) AND Unicode-3.0`); all are in the `deny.toml` allowlist (`cargo deny check licenses` passes). Redistribution requires shipping the licence texts with binaries; this joins the Phase H licence bundle.
4. **RustSec.** `cargo audit` (advisory database fetched 28 November 2026, 1571 advisories) reports no advisory for any crate above. Its 7 warnings (unmaintained `bincode`, `chrono`, `pin-utils`, `ttf-parser`, `zbus_names`, `zvariant`, `zvariant_derive`) predate this change and come from the Slint graph. The stack-overflow fixes in decision 2 are upstream bug fixes, not RustSec advisories.
5. **Direct and transitive dependencies.** Runtime graph of `framelet-settings`: `framelet-core`, `serde` → `serde_core`, `toml` → `serde_core`, `serde_spanned`, `toml_datetime`, `toml_parser` → `winnow`, `toml_writer`, `winnow`; compile time only: `serde_derive` → `proc-macro2`, `quote`, `syn`, `unicode-ident`. With these features `toml` does not pull `indexmap`, `foldhash`, `anstream`, or `anstyle`. Every crate was already in `Cargo.lock` through Slint (`toml` as a build dependency of `skia-bindings`; serde through `accesskit`/`zbus`); the change adds **no new crate** and bumps `toml` 1.2.1 → 1.2.3 and `toml_parser` 1.1.5 → 1.1.7 workspace-wide (also used by `skia-bindings`' build script and `toml_edit`). `cargo deny check bans` duplicate warnings are unchanged (26 before and after).
6. **Unsafe code and FFI.** No crate in the graph has native code, `extern` blocks, or links a native library. `toml`, `toml_writer`, `toml_datetime`, and `serde_spanned` declare `#![forbid(unsafe_code)]`. `toml_parser` forbids unsafe code unless its `unsafe` feature is enabled; nothing in the workspace enables it. `winnow` contains `unsafe` unchecked slicing in its stream implementations (about 47 occurrences, offsets checked by the callers); `serde`/`serde_core` use `str::from_utf8_unchecked` on buffers they formatted themselves (2 sites each); `unicode-ident` uses `get_unchecked` on a static table with a masked index; `proc-macro2`/`syn` contain unsafe code but run only inside the compiler as part of `serde_derive`. Build scripts: `serde`, `serde_core`, `proc-macro2`, `quote` run `rustc --version` and emit `cfg`s; `serde`/`serde_core` also write a generated module to `OUT_DIR`. Procedural macro: `serde_derive` (compile time only, generates safe code). None of this unsafe code was audited line by line; it is accepted on the strength of upstream maintenance, the absence of advisories, and the safe public APIs.
7. **Windows and Linux behaviour.** Pure Rust, no platform-specific code in `toml`/`serde`; no runtime files or plugins to package. Platform differences are in the adapter: Unix applies `0700`/`0600` modes, Windows relies on the per-user ACL of `%APPDATA%`; `std::fs::rename` replaces the target atomically within one volume on both (on Windows it fails if another process holds `settings.toml` open without delete sharing, which surfaces as `WriteFailed` with the old file intact).
8. **Documented here; `cargo vet`; changed exposure.** Until now `toml`/`toml_parser` ran only at build time, as a build dependency of `skia-bindings`, on inputs from the build itself. With this change they ship in the application and parse, at runtime, a file any process of the user can write and the user edits by hand — untrusted input. The review bar is therefore that of a parser of untrusted data: the input is bounded to 64 KiB before parsing, parsing errors are typed and never panic, deep nesting and long dotted keys are rejected by `toml_parser`'s recursion guard (tested), and the pinned versions contain the upstream stack-overflow fixes. A line-by-line audit of `toml_parser` and `winnow` has **not** been done; the maintainer should decide whether to require one (or to trust the publisher) before accepting this ADR. No imported audit set (Bytecode Alliance, Google, Mozilla, Zcash) covers these versions. `cargo vet` recommends trusting the publisher `epage` for `toml`/`toml_parser`, as Mozilla and the Bytecode Alliance do; that is a trust-policy decision left to the maintainer. Instead the two existing exemptions were moved to the new versions (`toml` 1.2.3, `toml_parser` 1.1.7) with a note that they are **exemptions, not audits**; the other crates above were already exempted. An exemption records that the crate has not been vetted.

## Alternatives considered

- **Keep `load -> Result<RecordingSettings, PortError>`** and let the caller substitute defaults: rejected; "nothing stored" would look like an error or the error would be lost, and the reason would be a string.
- **Clamp or partially accept invalid files** (keep valid fields, default the rest): rejected; values the user did not choose would become active without notice. Cost of the chosen policy: one invalid value resets all settings to defaults until the file is fixed or saved again.
- **Ignore unknown keys** for forward compatibility: rejected in favour of a schema-version bump per added key, which keeps typos visible.
- **`toml_edit`** to preserve user comments on save: rejected for now; more code and API surface for a file Framelet writes itself.
- **`serde_json`, RON, or an INI-style hand-written format:** rejected; TOML is named in the specification and is the most readable for hand edits.
- **`dirs`/`directories` crate** (Windows Known Folder API, XDG lookups): rejected per maintainer decision; the environment variables are the documented interface on both platforms, and a missing variable is reported as `LocationUnavailable` instead of guessed. Revisit if real users hit redirected or missing `APPDATA`.
- **Settings in the storage crate or the desktop crate:** rejected; it would mix persistence concerns or put file I/O in the composition root/UI crate (REQ-ARCH-03).
- **File locking against concurrent instances:** deferred; a single-instance policy for the desktop app is the better place to decide it.

## Consequences

- C-7 is testable and tested (validation below), but not checked until acceptance and a Windows CI run. Missing, malformed, unknown-version, out-of-range, unreadable, and unwritable settings never crash, never lose the previous file, and always yield usable settings plus a typed reason.
- The port is not consumed yet. The C2 slice must construct `TomlSettingsFile` in `apps/desktop` (composition root), call `load`/`save` on a worker, show `LoadedSettings::error()` and `save` errors in the UI (REQ-CFG-03, REQ-ERR-02), and feed `output_directory` into the storage adapter and recovery scan; the desktop's current `default_output_directory` lookup must then be reconciled with REQ-STOR-06.
- `crates/settings` is the only crate allowed to depend on serde/toml; another persistence format needs an ADR and a change to `scripts/check-architecture.py`.
- SPECIFICATION.md gains §7.1 (REQ-CFG-01 … 05) and names the module `settings` instead of `config` in §5 to match the maintainer decision.
- Windows reports opening a directory as access denied and a file in place of the settings directory as "not found"; the adapter checks for both so the typed error is the same as on Linux (`NotAFile`).
- Accepted costs: user comments are dropped on save; power-loss durability is not claimed; concurrent saves are last-writer-wins; Windows tests (`windows_location_*`, the Windows branch of the read-only test) run only in the `windows` CI job.

## Validation

- Core: `framelet_core::settings::tests::*` (invariant accepted and rejected cases, inclusive length boundary, defaults, origin/error mapping, messages); `framelet_core::contract::tests::fake_settings_*`.
- Adapter: `framelet_settings::tests::*` — schema mapping (complete and minimal files, malformed with line, missing/unsupported versions including `0`, `-1`, `i64::MAX`, `i64::MIN`, unknown keys and wrong types with line, every `OutputDirectory` violation, 30 000-deep nesting and 20 000 dotted keys rejected without a crash, round trip with quotes, backslashes, and non-ASCII); real files (missing → defaults and nothing created, a non-regular file (Unix socket standing in for a FIFO, which std cannot create without FFI) rejected before opening, an unopenable path is a read error and not "nothing stored", rejected files left unchanged, inclusive 64 KiB limit, non-UTF-8, directory at the path, parent is a file, read-only file not replaced, Unix read-only directory and unreadable file, owner-only modes); injected failure at every save step (create directory, create temporary, partial write, sync, rename) with the old file byte-identical and no temporary file left, failed first save leaves nothing, failed cleanup leaves only an ignored temporary file, stale temporary names skipped and exhausted; platform location rules.
- Contract: `crates/settings/tests/contract.rs` runs every `framelet_core::contract::settings` suite against `TomlSettingsFile`.
- The Unix permission tests skip with a message when the process bypasses permissions (root). On 28 November 2026 the final test binaries were run both as root (two tests skipped, as designed) and as an unprivileged user (uid 65534, no skips, all passed) in a Linux container.
- C-7 stays unchecked until this ADR is accepted and a green `windows` CI job is linked; REQ-CFG-01 … 05 stay at `implemented` until then.
- Mutation testing (cargo-mutants 27.1.0, run as root on Linux, final code): `crates/core/src/settings.rs` 11 mutants — 6 caught, 5 unviable, 0 missed. `framelet-settings` 62 mutants — 49 caught, 7 unviable, 6 missed, each justified: three mutate the guard that treats a file vanishing *between* the type check and the open as "nothing stored" — that race cannot be reproduced deterministically, and the "always true" variant is killed by `unreadable_file_loads_defaults_with_error` when the tests run unprivileged (it skips as root); the `is_dir` guard before a save is equivalent on Linux (rename onto a directory also fails as `NotAFile`) and exists for Windows, which reports it as access denied; `windows_settings_path` is exercised only by the Windows-only location tests; `StdFileOperations::sync_all` cannot be observed without a power loss. Earlier runs killed or removed the other survivors (a redundant guard in the read-only check was removed; `unopenable_path_is_a_read_error_not_missing_settings` and `non_regular_file_is_rejected_before_opening` kill the open-error guards for every user).
